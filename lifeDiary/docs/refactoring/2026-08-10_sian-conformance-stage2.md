## 한 것

### B4 카테고리 설명 예시 칩 (시안 7a)

`category-guide__row`를 2열에서 시안의 3열
(`minmax(160px,172px) 1fr minmax(180px,210px)`)로 바꾸고 예시 태그 칩 열을 넣었다.

예시는 `views.CATEGORY_EXAMPLE_TAGS` 의 정적 큐레이션이다. 사전 명세는 기본
`Tag` 레코드에서 뽑자고 했으나 D1이 공유 기본 태그를 없애므로 반려했다
(계획서 R2). 안내 화면의 예시일 뿐 사용자 데이터가 아니다.

칩은 읽기 전용이라 클릭 핸들러도 `tabindex`도 붙이지 않는다. 포커스는 가능한데
아무 일도 안 하는 요소는 키보드 함정이다.

모듈 수준 상수라 `gettext_lazy`를 쓴다. `gettext`면 임포트 시점 언어로 굳는다.

### B2 일 탭 `슬롯` · `7일 평균 대비` (시안 3b)

`슬롯`은 이미 `daily.py`가 `blocks`로 세고 있어 표에 꺼내기만 했다.

`7일 평균 대비`는 신규 — `aggregation/daily_baseline.py`. 기준일을 포함한
지난 7일의 태그별 하루 평균과 기준일 실제 기록의 차이다.

**시안 4b는 하루 구성을 3열로 유지한다.** 두 신규 열은 `is-wide-only`로
575.98px 이하에서 숨긴다. stats는 단일 템플릿 + 미디어 쿼리 구조라 템플릿을
가르지 않았다.

### B1 월 탭 주차별 요약 (시안 3d·4d)

**추가가 아니라 교체다.** 시안은 월 탭에서 태그 합계를 빼고 주차별 요약을
둔다. 구현은 정확히 반대(태그 순위만)였다.

`aggregation/weekly_summary.py` 는 월 집계에서 파생하므로 추가 조회가 없다.
주는 달력 주(월~일)로, 롤링 7일인 시안과 갈리는 승인된 이탈을 따른다.

`집중` 열 머리글은 고정 문구가 아니라 그 달 상위 태그의 이름이다. 시안의
"집중"은 태그 이름일 뿐이다.

갈린다"고 지적한 건이다.

## 잡은 버그

**기록 열이 미기록 시간을 세고 있었다.** `monthly_stats["daily_totals"]`에는
`fill_empty_slots_monthly`가 미분류를 채워 하루가 늘 24h다. 그대로 쓰면 기록이
전혀 없는 미래 주까지 168h로 보고된다. 태그가 붙은 시간만 합산하도록 고치고
회귀 테스트로 고정했다(`TestUnrecordedTimeIsNotCounted`).

브라우저 실측 전에는 테스트가 통과했다 — 합성 픽스처가 `daily_totals`와
태그 시간을 일치시켜 두어 차이가 드러나지 않았다. 실제 데이터로 화면을 봐야
잡히는 종류였다.

## 쿼리 예산

`TARGET_MAX_QUERIES` 를 16 → 17로 올렸다. `7일 평균 대비`의 창은 기준일 기준
지난 7일이라 월초에 전달로 넘어가고, 월간 조회를 재사용할 수 없다. 기록량과
무관한 상수 1회이며 근거를 테스트 주석에 남겼다.

## 검증 중 겪은 함정

1. **`runserver --noreload`** 로 띄운 서버가 수정 전 코드를 물고 있었다.
   화면이 안 바뀌면 코드부터 의심하기 전에 서버가 새 코드를 읽었는지 본다.
2. **통계 컨텍스트 캐시** — 과거 날짜는 TTL이 길어 수정 후에도 옛 수치가
   나온다. `cache.clear()` 후 재확인해야 한다.
3. **정적 파일 브라우저 캐시** — JS를 고친 뒤에는 캐시 무시 리로드가 필요하다.

세 번 모두 "코드가 틀렸다"로 오진할 뻔했다.
