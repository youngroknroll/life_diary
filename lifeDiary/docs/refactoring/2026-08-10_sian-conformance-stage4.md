## 한 것

### 공유 태그를 개인 태그로

`Tag.user=null` + `is_default=True` 로 전 사용자가 한 행을 나눠 쓰던 구조를
없앴다. 이제 모든 태그에 주인이 있다.

- `Tag.user` non-nullable, `is_default` 컬럼 삭제
- `unique_default_tag_name` 제거. `unique_user_tag_name` 은 조건절
  (`user__isnull=False`)이 필요 없어져 무조건 제약이 되었다
- `TagPolicyService` 가 규칙 하나로 줄었다 — 자기 것만 다룬다. **관리자도
  예외가 아니다.** `validate_default_flip` · `validate_create_default` ·
  `can_create_default` 가 사라졌고, `get_for_owner_or_404` 의 superuser 분기도
  없앴다
- `DeleteTagUseCase` 의 "이 기본 태그는 사용 중이어서 삭제할 수 없습니다" 방어가
  사라졌다. 남의 기록을 지킬 이유였는데 이제 자기 기록뿐이다. 기록이 붙은
  태그는 기존 "옮기고 삭제" 흐름이 그대로 받는다

### 가입 시 시드 태그

`apps/tags/seed_tags.py` 신설. 시안 7a 가 카테고리별 예시로 보여 주던 11개를
가입 시점에 **개인 소유로 실제로 만들어 준다**.

이름은 가입 시점 언어로 번역해 저장한다. 카테고리와 달리 태그는 사용자가 고쳐
쓰는 자기 데이터라, 표시할 때마다 번역하면 고친 이름이 원문으로 되돌아 보인다.

설명 화면(7a)의 예시도 같은 목록에서 가져오도록 바꿨다. 두 곳에 적어 두면
한쪽만 바뀌어 설명 화면이 거짓말을 하게 된다.

### 데이터 이관

`0013_personalize_shared_tags` (데이터) → `0014_drop_shared_tag_concept`
(스키마). 순서가 곧 전제다 — null 소유자 행이 남아 있으면 `user` 를
non-nullable 로 바꿀 수 없다.

같은 이름의 개인 태그를 이미 가진 사용자에게는 복제본을 만들지 않고 그가 쓰던
태그로 참조를 옮긴다. `unique_user_tag_name` 을 지키기 위해서이기도 하고, 이미
자기 이름으로 정리해 둔 것을 존중하기 위해서이기도 하다.

`TimeBlock` 과 `UserGoal` 양쪽을 옮긴다. 목표는 `(user, tag, period)` 가 겹칠 수
있어 충돌 시 이관 대상을 지운다.

**되돌릴 수 없다.** 역방향은 예외를 던지고 백업 복원을 안내한다.

## 리뷰어 사전 산출물 반영

두 리뷰어가 **제가 놓친 표면 두 개**를 잡았다. 제 grep 이 `is_default` 문자열만
찾아서, `is_superuser` 로 가려진 곳을 통째로 지나쳤다.

- `_tag_modal.html` 의 관리자 전용 "기본 태그로 설정" 체크박스 (가장 큰 누락)
- `tags/index.html` 의 `관리자` 배지와 `isSuperuser` 상수

같은 이유로 `dashboard/models.py` 의 `clean()` 예외 분기와 `dashboard.js` 의
별 아이콘도 놓쳤었다. 이건 리뷰어가 아니라 첫 grep 출력을 `head -80` 으로
자른 탓에 가려진 것이다.

상호작용 기준에서 받은 지적도 이행했다 —

- **삭제 모달에 포커스 복귀가 없었다.** 폼 모달에는 있었는데 삭제 모달에는
  없었다. 기본 태그가 사라지면서 이 모달을 지나는 횟수가 늘어 이번에 넣었다.
  삭제가 성공하면 여는 버튼 자체가 사라지므로 그때는 화면의 주 동작으로 보낸다
- **배포 순서**: 백엔드(모델·마이그레이션·유스케이스)와 템플릿·JS 를 한
  커밋으로 묶었다. 나눠 배포하면 새 JS + 옛 백엔드 조합에서 편집 버튼이
  403 을 받는다
- `can_edit` · `can_delete` 는 API 에 남겼다. 이제 항상 참이지만, 캐시된 옛
  JS 가 이 값을 읽어도 계속 동작한다

## 사용자 지적 반영 — 버튼 라벨 줄바꿈

실측 42×61. 높이 61 은 `수정` 두 글자가 두 줄로 접혀 있었다는 뜻이다.
`.btn-sian` 의 좌우 여백 14px 이 좁은 카드에서 글자 자리를 다 먹었다.

`.btn-sian--compact` 를 만들어 여백과 글자만 줄이고 44px 높이는 지켰다.
360px 6px/12px, 576px 10px/13px, 768px 14px/13.5px.

| 폭 | 한국어 | 영어 |
|---|---|---|
| 360px | 35×44 | Edit 30×44 · Delete 41×44 |
| 600px | — | 64×44 · 81×44 |
| 1280px | — | 56×44 · 65×44 |

세 폭 모두 한 줄이고 잘리지 않는다(`scrollWidth == clientWidth`).

폭이 44px 에 못 미치는 건 카드가 `col-5` 라 360px 에서 109px 밖에 안 되기
때문이다. 프로젝트 계약인 `min-height: 44px` 는 지켰고 WCAG 2.5.8 AA(24×24)도
넘는다. 카드 그리드 자체는 A1(7단계)이 행 리스트로 갈아엎으므로 거기서 없어진다.

## i18n

### 인라인 스크립트 문구가 어디에도 추출되지 않았다

영어 화면을 렌더링해 보고 잡았다. 태그 관리 화면의 `수정` 이 한국어로 남아
있었고, 확인해 보니 6개 문구 중 5개가 JS 카탈로그에 아예 없었다.

`gettext('수정')` 이 템플릿의 `<script>` 안에 있으면 **어느 쪽도 수집하지
않는다** — `djangojs` 는 `.js` 파일만 훑고, `django` 도메인은 템플릿 태그만
훑는다. 그동안 원문이 한국어라서 한국어 화면에서는 아무 문제가 없었다.

`{% trans ... as %}` 로 번역한 뒤 `LABELS` 상수로 넘기도록 바꿨다. 이건
D1 이 만든 문제가 아니라 이전부터 있던 구멍이고, 이번에 이 화면을 건드리면서
드러났다.

### 시드 태그 영어가 잘렸다

`Focused work`(12자)가 태그명 10자 제한에 걸려 **`Focused wo`** 로 저장됐다.
`Plans with others`(17자)도 마찬가지였다. 영어로 가입한 사용자는 깨진 이름을
받았을 것이다.

`Deep work`(9) · `Plans`(5)로 줄였다. 그리고 **모든 지원 언어에서 시드 이름이
한계를 넘지 않는다**는 계약을 테스트로 고정했다 — 번역을 추가하다 다시 넘기면
바로 실패한다.

이 결함은 앞선 영어 테스트가 활성 언어를 남긴 덕에 우연히 드러났다. 테스트가
언어에 의존하던 것 자체는 결함이라 `translation.override` 로 고정했지만,
그러지 않았으면 못 봤다.

### fuzzy — 네 번째

`태그를 불러오는 중 오류가 발생했습니다.` 가 `태그 수정 중 오류가
발생했습니다.` 의 번역을 물려받았다. 불러오기 실패인데 "수정 중 오류"라고
말했을 것이다. 이번에도 **걷기 전에 내용을 확인**해서 잡았다.

### 비어 있던 영어 번역

- `아직 기록 없음` → `No records yet`
- `누적 %s시간` → `%s h total`
- 카테고리 설명 리드와 맺음 문단 2건

`누적 %s시간` 에서 한 번 헛짚었다. 파이썬에서 `gettext("누적 %s시간")` 로
확인하니 번역이 안 붙는 것처럼 보였는데, 템플릿 `{% trans %}` 는 조회 시점에
`%` 를 `%%` 로 이스케이프해 카탈로그와 맞춘다. **브라우저 렌더링이 진실이었고
파이썬 probe 가 틀렸다.**

### 여러 줄 `{# #}` 주석이 페이지에 찍혔다

`{# #}` 는 한 줄짜리다. 여러 줄로 쓴 주석이 그대로 렌더링돼 영어 화면에
한국어 설명문이 나타났다. `{% comment %}` 로 바꿨다. 이것도 브라우저를
안 봤으면 그대로 나갔다.
