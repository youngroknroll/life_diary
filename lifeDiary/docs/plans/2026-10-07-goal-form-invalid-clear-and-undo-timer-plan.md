# 목표 표 오류 표시 해제·되돌리기 타이머 계획 (2026-10-07)

- 브랜치: `feat/goal-due-date` (PR #89에 이어 붙인다)
- 상태: 승인 (2026-10-07)

## 배경

`docs/refactoring/2026-10-07-goal-form-focus-and-field-errors.md` "남은 일"의 두 건. 사용자가 2026-10-07에 해결을 지시했다.

1. 거부(422)된 칸을 사용자가 고쳐도 다시 저장하기 전까지 `aria-invalid`·`aria-describedby`와 오류 배경이 남는다. 스크린리더는 이미 고친 칸을 옛 문구와 함께 오류로 읽는다. 행은 dirty 테두리(초록)와 오류 배경이 섞이고, 추가 폼은 dirty 상태가 없어 계속 빨갛다.
2. 삭제 뒤 8초 자동 숨김 타이머가 진행 중인 되돌리기 요청을 모른다. 8초 직전에 되돌리기를 누르면 응답 전에 스낵바가 사라지고, 요청이 실패하면 다시 시도할 수단이 없다.

## 승인 범위

### A. 고친 칸의 오류 표시 해제

- 사용자가 칸을 고치면(`input`·`change`) 그 칸이 속한 묶음의 `aria-invalid`·`aria-describedby`를 지운다. 오류 색은 `[aria-invalid="true"]`에만 칠하므로 함께 사라진다.
- 묶음(서버가 실제로 내는 `error_field`는 `due_date`, `target_hours`, `__all__` 셋이다):

| 고친 칸 | 지우는 표시 |
|---|---|
| 기한 날짜 | 기한 |
| "기한 없음" 체크박스(체크·해제 모두) | 기한. 체크하면 날짜 칸이 비활성이 되므로 "비활성인데 오류"인 상태도 없앤다 |
| 목표 시간 | 목표 시간 |
| 기간 | 태그·기간(중복 묶음), 목표 시간(상한이 기간에 따라 바뀐다) |
| 태그 | 태그·기간(중복 묶음) |

- 원인과 무관한 칸을 고치면 표시를 남긴다.
- 그 폼에 오류 표시가 하나도 남지 않으면 오류 문구 `<p>`를 지운다. 칸의 속성을 먼저 지우고 문구를 지운다(끊긴 `aria-describedby` 참조가 남지 않게). 추가 폼은 그 자리에 기존 힌트("일간 최대 24h · 주간 100h · 월간 300h")를 되돌린다. 이를 위해 템플릿이 오류가 있을 때도 힌트를 `hidden`으로 함께 그린다.
- 포커스는 옮기지 않는다. 요청을 보내지 않는다. 라이브 리전에 알리지 않는다. 지운 칸을 기억하는 전역 상태를 두지 않는다(다시 그리면 서버가 그린 상태만 남는다).
- 고쳤다가 원래 값으로 되돌려도 지운 표시는 돌아오지 않는다. 다음 제출에서 서버가 다시 판정한다.
- 선례: `users/js/signup-validate.js` `clearConsentError`(컨트롤 변경 시 `aria-invalid`·`aria-describedby` 제거 + 오류 문구 비움).

### B. 되돌리기 요청 중 스낵바 유지

- 되돌리기 요청이 실제로 나갈 때(진행 중인 다른 요청이 없을 때) 자동 숨김 타이머를 멈춘다. 다른 요청이 진행 중이라 되돌리기가 나가지 않으면 타이머도 그대로 둔다(멈추기만 하고 다시 걸리지 않으면 스낵바가 영원히 남는다).
- 성공: 지금과 같다(복원된 행 태그 칸에 포커스, 스낵바 숨김).
- 실패(422, 네트워크): 스낵바를 남기고 8초 타이머를 처음부터 다시 건다. 버튼은 잠금이 풀려 다시 누를 수 있다. 다시 거는 동작은 숨김 함수를 부르지 않는다(422의 포커스 이동과 겹치지 않게).

## 제외 범위

- 스낵바 라이브 리전 부재, 전역 `busy` 플래그, `dashboard.js` 되돌리기 설계(다른 트레이드오프로 이미 경합이 없다).
- 오류 문구를 칸마다 따로 두는 구조.

## 수락 기준

1. 원인과 무관한 칸을 고치면 오류 칸의 `aria-invalid`·색·오류 문구가 남는다.
2. 기한 오류에서 날짜를 입력하거나 "기한 없음"을 체크·해제하면 기한 칸의 `aria-invalid`·`aria-describedby`가 바로 사라지고, 남은 오류가 없으면 오류 문구가 사라진다.
3. 시간 초과 오류에서 시간을 입력하거나 기간을 바꾸면 시간 칸 표시와 오류 문구가 사라진다.
4. 중복 오류에서 태그나 기간 하나만 바꿔도 두 칸 모두 풀리고 오류 문구가 사라진다.
5. 추가 폼도 1~4와 같고, 오류 문구가 사라진 자리에 힌트가 보인다.
6. 표시를 지울 때 `document.activeElement`가 고치던 칸에서 벗어나지 않고, 네트워크 요청이 없다.
7. 행에서 고치면 저장 버튼이 표시 해제와 같은 동작에서 나타난다(기존 dirty 판정 유지).
8. 되돌리기 요청이 8초를 넘겨도 응답 전에 스낵바가 사라지지 않는다.
9. 되돌리기 성공 뒤 스낵바는 숨은 채로 남는다(8초 더 기다려도 다시 뜨지 않는다).
10. 되돌리기 422·네트워크 실패 뒤 스낵바가 남고, 버튼을 다시 누를 수 있고, 8초 뒤 숨는다.
11. 다른 행 저장이 진행 중일 때 누른 되돌리기는 요청을 보내지 않고, 스낵바는 원래 타이머대로 숨는다.
12. 새 CSS·색 토큰·사용자 문자열 없음. 1280·375px 가로 넘침 없음, 44px 터치 영역 유지. 콘솔 JS 오류 0건, `node --check` 통과, 다크·라이트·ko·en.
13. 전체 pytest가 통과한다(템플릿 변경이 기존 렌더 테스트를 깨지 않는다).

## Frontend Review Evidence

### Web Experience Designer 사전 명세 (요약)

- 고친 칸의 빨간 테두리·배경·오류 문구가 재제출 전에 사라진다. 무관한 칸은 표시 유지. 행은 기존 dirty 상태로 넘어간다.
- 묶음: 기한 ← 날짜·체크박스, 시간 ← 시간·기간, 중복 ← 태그·기간. 오류 문구는 남은 표시가 없으면 완전히 지운다(접근성 트리에서도). 추가 폼은 힌트를 되돌린다.
- 지우는 순서: 속성 먼저, 문구 나중. 포커스 이동·라이브 리전 알림 없음.
- 스낵바: 요청 중에는 사라지지 않고, 실패하면 남아서 새로 8초. 남은 시간을 추적하지 않는다.
- 레이아웃 변화는 오류 문구 한 줄 높이로 한정. 새 CSS·토큰·문자열 없음.

### Browser Interaction Reviewer 사전 기준 (요약)

- A1 숫자·날짜는 `input`, 셀렉트는 `change`에서 지운다(blur 전에도 지워져야 한다). A2 체크박스 변경은 기한 표시를 지운다. A3 중복 묶음은 함께 지운다. A4 넓은 범위로 지우지 않는다(고치지 않은 칸 유지). A5 마지막 표시가 지워지는 같은 이벤트에서 문구도 지운다. A6 추가 폼에 `input` 연결이 새로 필요하다. A7 저장 버튼 노출과 표시 해제가 같은 이벤트에서 일어난다. A8 전역 상태를 두지 않는다.
- B1 타이머는 `busy` 확인 뒤 요청이 확정될 때만 멈춘다. B2 성공 뒤 다시 뜨지 않는다. B3·B4 422와 네트워크 실패 모두 다시 건다. B5 다시 걸 때 숨김 함수를 부르지 않는다. B6 되돌리기 중 다른 삭제는 `busy`가 막는 현재 동작 유지.
