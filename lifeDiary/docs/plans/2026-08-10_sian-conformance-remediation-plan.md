## 확정된 결정 (2026-08-10 사용자)

### D1. 기본 태그 개념을 없앤다

`Tag.user=null` + `is_default=True`로 전 사용자가 공유하던 기본 태그를
폐지하고, 모든 태그를 개인 태그로 만든다. 가입 시 시드 태그 집합을 개인
태그로 생성한다.

이유 — 시안 6a는 행 드래그 정렬과 인라인 이름 편집을 요구하는데, 공유
객체에는 사용자별 순서와 이름을 적을 수 없다. 채택 집합 표를 두어도 결국
순서·이름까지 그 표가 떠안게 되어 복제와 데이터량이 같아진다.

파급 —
- `Tag.user` 가 non-nullable 이 되고 `is_default` 컬럼이 사라진다
- `unique_default_tag_name` 제약 제거, `unique_user_tag_name` 만 남는다
- 기존 데이터 마이그레이션: 공유 기본 태그를 사용하던 사용자별로 복제한 뒤
  공유 행을 삭제한다. `TimeBlock` 참조를 복제본으로 옮겨야 하므로 되돌릴 수
  없는 마이그레이션이다 — 사전 백업 필요
- 관리자 전용 경로(`is_superuser` 분기, 기본 태그 배지·보호 로직)가
  `views.py`·`tag.js`·`_tag_modal.html`·`tags/index.html`에서 정리된다
- **시안 이탈 신설**: 시안 6a의 `[기본]` 배지가 사라진다

### D2. 달성률 분모는 지난 시간 기준

시안 6c대로 아직 오지 않은 시간을 분모에서 뺀다. 함께 **현재 적용된 룰
기반 피드백을 제거한다**(사용자 결정). `apps/stats/life_feedback.py` 와
그 호출부·템플릿·테스트가 정리 대상이다.

### D3. 태그 이름 최대 10자

`max_length=50` → 10. 설명이 필요한 경우는 기록 저장 시의 메모로 갈음한다
(사용자 결정). 시안 7b의 "최대 12자"와 갈리는 지점이다.

기존 10자 초과 태그 처리 방침을 마이그레이션에서 정해야 한다 — 절삭 시
`unique_user_tag_name` 충돌 가능성이 있으므로 충돌 해소 규칙이 필요하다.

### D4. 비밀번호 변경 기능 신설 (2026-08-10 사용자)

로그인 상태에서 현재 비밀번호를 확인하고 새 비밀번호로 바꾸는 흐름이 없다.
기존 `password_reset_*`은 비로그인 상태의 찾기 흐름이라 대체가 안 된다.
Django `PasswordChangeView` 계열을 쓰되 이 저장소의 인증 화면 스킨
(`auth-panel`, `btn-sian`, 필드 인라인 오류)을 따른다. 1단계에 포함한다.

채택한 핵심 지침 —

- **5c 섹션 순서**: 목표 시간(인라인 표) → 태그와 카테고리(칩 + 5색 범례 +
  "태그 카테고리 설명 보기 ›") → 표시·계정 2단 그리드. 하단 단독 "계정 탈퇴"
  카드는 없애되 **15일 유예 안내 문구는 삭제하지 말고 탈퇴 확인 페이지로 옮긴다.**
- **목표 표 열 축소**: `태그 | 기간 | 목표 | 삭제`. 달성률·실제 기록은 분석
  탭 소관이라 설정에서 뺀다(현행 `_goal_table_section.html`은 6열).
- **A1 미구현으로 인한 잠정 이탈**: 칩 클릭 편집은 A1(7단계)이 있어야 성립하므로,

- **B2 모바일**: 시안 4b의 하루 구성은 3열을 유지한다. 슬롯·7일 평균 대비는

### Browser Interaction Reviewer 사전 기준 (1~3단계)

**저장소 전역 격차 — 먼저 해결한다.** `.data-table`에 반응형 래퍼가 코드베이스
어디에도 없다. B1·B2·A2가 각각 표를 늘리거나 새로 만들므로, 세 곳이 제각기
다른 방식으로 넘침을 막기 전에 **공용 `.table-scroll` 유틸리티를 먼저 만들고**
셋 다 그것을 쓴다. 수용 게이트는 360px에서
`document.documentElement.scrollWidth === clientWidth`.

**B5 로그인 실패** — 실패 응답에서 포커스가 정정할 입력으로 이동해야 한다
(현재 `views.py`가 재포커스를 하지 않아 문서 최상단에 남는다). 오류 노드는
`aria-describedby`로 입력과 연결하고 입력에 `aria-invalid="true"`를 건다.
"2회 남음"은 **오류 메시지와 같은 노드**에 넣어 한 번만 낭독되게 한다
(별도 live region 금지). 전체 리로드 방식이므로 오류 자체에는 live region이
불필요하다. reCAPTCHA 노출 상태와 인라인 오류가 360px에서 겹치지 않아야 하고,
성공 로그인 시 잔여 오류·`aria-invalid`가 남지 않아야 한다.

**B6 회원가입** — 동의 체크박스는 `label for` 연결, 탭 순서는
아이디→이메일→비밀번호→확인→동의→제출. 미체크 시 클라이언트·서버 양쪽에서
차단하고 포커스를 체크박스로 옮긴다. 라벨 개명 시 `for`/`id` 쌍 유지.
기존 아이디·이메일 중복 확인의 경쟁 조건(stale 응답 폐기)이 깨지지 않아야 한다.

**B4 카테고리 예시 칩** — 읽기 전용이므로 클릭 핸들러·`tabindex="0"`를 달지
않는다(포커스 가능하지만 아무 일도 안 하는 요소는 키보드 함정). 360px에서
3열 그리드가 넘침 없이 접혀야 하고, 대비는 실제 렌더된 조합으로 확인한다
(가장 불리한 `#C99A2E` 기초 생활시간부터).

**A4 카테고리 5카드** — 단일 `role="radiogroup"` + 그룹 라벨, 각 카드
`role="radio"` + `aria-checked`. **roving tabindex**로 그룹 전체가 탭 정지
하나여야 한다. 방향키 이동만으로 선택이 따라가야 하고(Enter/Space 불필요),
포커스 링과 선택 상태를 시각적으로 구분해야 한다. 색 미리보기는 클릭뿐 아니라
**방향키 이동마다** 갱신되어야 한다. Bootstrap 모달 안에 유지해 포커스 트랩·
Escape·백드롭·트리거 복귀를 그대로 상속받는다(커스텀 오버레이 금지).
편집 모드 재진입 시 해당 카드가 선택·포커스 가능 상태로 복원되어야 한다.

**A2 설정 목표 인라인 표** — 삭제 후 포커스가 사라진 행에 남으면 안 된다
(`activeElement === body`면 실패). 기존 `goalSaveStatus`의
`role="status" aria-live="polite"`를 재사용해 한 동작에 한 번만 알린다.
요청 중 버튼 비활성화로 중복 DELETE를 막고, **서버 확인 전에 행을 낙관적으로
지우지 않는다**(롤백 없는 즉시 삭제는 결함). 회원 탈퇴는 스킨을 바꿔도 색
이외의 위험 신호(문구·아이콘)를 유지한다.

**C1/C2** — 재스킨 대상 버튼과 `target_hours` 입력이 360px에서 44×44px 이상을
유지해야 한다(제거하는 인라인 `<style>`가 현재 폭을 강제하고 있다).
`mypage.html`에 포함되는 `usergoal_list.html`의 버튼도 같은 패스에 포함한다.
- 계획 브라우저 증거 — 360px·760px·1280px 렌더, 콘솔 점검,
  변경 JS `node --check`, 드래그·모달 키보드 경로, 대비 확인

### 7단계 (A1) 리뷰 증거

사전 산출물을 **편집 전에** 두 리뷰어 모두에게서 받았다.

사전에 잡힌 것 —
- 행 리스트에서는 "수정"/"삭제" 만으로는 어느 태그인지 알 수 없다 (기존
  카드 배치부터 있던 미결 지적사항). 모든 버튼 `aria-label` 에 태그 이름을 넣었다
- `container.innerHTML +=` 는 붙일 때마다 이미 넣은 노드까지 새로 만든다.
  방금 누른 버튼이 사라져 포커스가 문서 바닥으로 떨어지므로 순서 변경과
  양립할 수 없다
- 인라인 `onclick` 의 문자열 보간 (`name: '${escapeHTML(tag.name)}'`) 은

- `미분류` 분기는 `Tag.category` 가 non-null 이라 도달할 수 없는 죽은 코드다
- 시안 6a 의 "인라인 편집" 은 카테고리 변경이 모달에 남는 이상 반쪽이 된다

### 확정된 결정 (2026-08-12 사용자) — A1 착수 조건

**1. 정렬 기본값은 좁게 바꾼다.** `Tag.Meta.ordering` 은 `["name"]` 을 유지하고
`TagRepository.find_accessible_ordered` 만 `display_order` 를 낀다.

이유 — `Meta.ordering` 은 `order_by` 를 쓰지 않는 모든 쿼리에 걸린다. 그중
`apps/stats/aggregation/summary.py` 의 색 조회는 사용자 스코프 없이
`.first()` 를 썼다. 4단계에서 태그를 전원 개인 소유로 쪼갠 뒤로 같은 이름이
사용자 수만큼 존재하므로 **남의 태그 색이 내 통계에 붙을 수 있었다.**
같이 고쳤다 — 색을 이름으로 되찾지 않고 집계하며 챙긴다.

**2. 순서는 카테고리 안에서만 움직인다.** `display_order` 는
`(user, category)` 안의 시퀀스다.

이유 — `Tag.save()` 가 색을 카테고리 색으로 덮어쓰고, 통계는
`block.tag.category` 를 매번 조인한다. 카테고리를 옮기면 색뿐 아니라 **과거
기록의 통계까지 소급해 바뀐다.** 손이 미끄러지는 것이 기본 실패 모드인
제스처에 묶을 변화가 아니다. 카테고리 변경은 편집 모달에 남는다.

**3. 드래그 대신 위/아래 이동 버튼.** 이번 단계는 버튼만 만든다.

이유 — 저장소에 드래그 전례가 0건이고 `package.json` 이 없어 라이브러리를
들이면 최초의 프론트 런타임 의존성이 된다. HTML5 드래그앤드롭에는 키보드
경로가 없어 이중 리뷰 게이트를 통과할 수 없다. 버튼과 드래그는 같은
엔드포인트를 부르는 표현 계층이므로 버튼이 먼저다.

**시안 이탈 신설 두 건** — 시안 6a 의 행 드래그가 없다. 시안 6a 의 "인라인
편집" 은 같은 행에서 이름을 고치는 것이 아니라 행에서 바로 열리는 모달이다.
