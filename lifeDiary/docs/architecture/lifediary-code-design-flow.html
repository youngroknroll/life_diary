LifeDiary 코드 설계 및 흐름도

이 문서는 현재 코드베이스를 기준으로 LifeDiary의 Django 앱 구성, 레이어 의존 방향, 주요 데이터 모델, 사용자 요청 흐름을 한 화면에서 파악할 수 있도록 정리한 정적 HTML 문서다.

기준일: 2026-05-26 프레임워크: Django monolith 주요 흐름: views → use_cases → repositories/domain_services → models

1. 시스템 개요

Product

10분 단위 생활 기록

하루를 144개 슬롯으로 나누고, 사용자가 선택한 시간 구간에 태그와 메모를 저장한다.

Review

통계와 목표 회고

일간, 주간, 월간 집계를 만들고 목표 달성률과 규칙 기반 라이프 피드백을 함께 제공한다.

Delivery

웹 + 데스크톱 기반

Django 웹 앱을 중심으로 구성되어 있으며, 데스크톱 런처는 waitress와 pywebview로 같은 UI를 띄운다.

6. 시간 기록 저장 흐름

  1. 사용자 대시보드에서 날짜와 10분 슬롯을 선택하고 태그/메모를 입력한다.
  2. dashboard.views time_block_api가 JSON을 읽고 UpsertTimeBlocksCommand로 검증 가능한 입력 객체를 만든다.
  3. UpsertTimeBlocksUseCase 접근 가능한 태그인지 TagRepository.find_by_id_accessible로 확인한다.
  4. TimeBlockRepository 같은 날짜와 슬롯의 기존 기록을 조회하고, 새 슬롯은 생성 목록에, 기존 슬롯은 수정 목록에 담는다.
  5. Database bulk_create와 bulk_update로 저장한다. unique_user_date_slot 제약이 중복 기록을 막는다.
  6. stats cache 저장된 날짜의 통계 캐시를 한국어, 영어, 기본 언어 키 기준으로 무효화한다.
  7. JSON response 생성/수정 개수와 태그 정보를 반환해 프론트엔드가 슬롯 UI를 갱신한다.

캐시 정책

과거 날짜는 24시간, 오늘 날짜는 5분 TTL을 사용한다. 언어별 표시가 달라질 수 있어 캐시 키에 언어가 포함된다.

집계 축

일간, 주간, 월간, 태그 분석 데이터를 만들고 Chart.js용 JSON 구조도 같은 컨텍스트에 담는다.

피드백 규칙

목표 달성, 특정 태그 과점, 활동 변동성, 수면 과다, 미분류 과다를 규칙으로 판정한다.

8. 태그 관리 흐름

  1. 사용자 태그 이름, 색상, 카테고리를 입력한다. 관리자는 기본 태그를 만들 수 있다.
  2. tags.views 요청 데이터를 읽어 생성, 수정, 삭제 use case를 호출한다.
  3. TagPolicyService 기본 태그 생성/전환 가능 여부와 편집/삭제 권한을 판단한다.
  4. TagRepository 사용자 소유 태그와 기본 태그의 접근 가능 범위를 일관되게 조회한다.
  5. CategoryRepository 카테고리 존재 여부를 확인하고, Tag 모델은 HEX 색상과 이름 제약을 검증한다.

태그 접근 정책은 시간 기록 저장과 목표 저장에서도 반복 사용된다. 이 구조 덕분에 다른 사용자의 비공개 태그를 참조하는 입력은 저장 전에 차단된다.

9. 인증, 목표, 메모 흐름

인증

  • 회원가입 후 welcome 화면으로 이동한다.
  • 로그인은 remember-me 14일 세션을 지원한다.
  • 실패 횟수 기준으로 reCAPTCHA 요구 상태를 캐시에 기록한다.
  • 삭제 유예 중인 계정은 올바른 로그인으로 삭제 요청을 취소할 수 있다.

목표와 메모

  • SaveGoalUseCase는 접근 가능한 태그인지 먼저 확인한다.
  • UserGoal.full_clean()이 기간별 목표 상한을 검증한다.
  • GetMyPageUseCase는 필요한 기간 통계만 계산하고 목표 진행률을 붙인다.
  • NoteRepository는 최신 메모 조회와 저장/삭제 경계를 담당한다.

11. 설계상 중요한 규칙

슬롯 무결성

하루는 144개 슬롯이며, 사용자/날짜/슬롯 조합은 DB 제약으로 유일하다.

태그 소유권

기본 태그는 공용이고 사용자 태그는 소유자만 접근한다. 저장 흐름에서 접근 가능 여부를 확인한다.

통계 캐시 일관성

시간 블록 저장/삭제 후 해당 날짜 통계 캐시를 무효화해 오래된 통계가 남지 않게 한다.

미분류 시간

기록되지 않은 시간도 통계와 피드백에서 의미 있는 회고 데이터로 취급한다.

검증 위치

요청 형식은 command/form에서, 소유권은 repository/use case에서, 데이터 제약은 model에서 보강한다.

모놀리스 유지

앱 경계를 나누되 배포와 런타임은 Django 모놀리스를 유지하는 보수적 구조다.

작성 기준 파일: lifeDiary/urls.py, apps/dashboard/*, apps/tags/*, apps/users/*, apps/stats/*, desktop/launcher.py, docs/project-status.md.
